版本對應 state / module和 code 的關係
Single FSMS_LB_INIT從 UrSRAM 讀灰階資料，載入 3-row line buffer，準備做 Gaussian
Modular v21threshold_v21_fast使用 3×3 Gaussian kernel [1 2 1; 2 4 2; 1 2 1] / 16
Single Submitthreshold state 1用 get_data_state 依序取得 u1~b3 九個鄰近 pixel

三個版本在此流程中的比較內容說明

在「Gaussian Window Fetch」流程中，三個版本都能對應到功能實作，但組織方式不同。Single FSM 版把功能集中在 S_LB_INIT，屬於 state-level 的集中控制。Modular v21 版對應到 threshold_v21_fast，通常由 top FSM 啟動特定子模組處理。Single Submit 版對應到 threshold state 1，雖然整份 code 合併在同一個檔案中，但功能仍由相對應的 module 或 internal state 完成。因此比較重點不是功能有沒有做，而是硬體排程方式、記憶體控制權與模組邊界不同。

// Function
//   1. Read original RGB pixels from ImgROM.
//   2. Convert RGB to grayscale with fixed-point round-to-nearest-even.
//   3. Apply 3x3 Gaussian smoothing with reflect-101 boundary handling.
//   4. Write filtered gray values to UrSRAM and build a 256-bin histogram.
//   5. Search Otsu threshold using integer cross-multiplied score comparison.
// ============================================================================

);
