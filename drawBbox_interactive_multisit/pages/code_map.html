程式區段總表

流程區段行號做什麼為什麼重要
一、Module 介面與記憶體協定1–25定義 top module 的 I/O 與 ImgROM、UrSRAM、AnsSRAM 的讀寫介面。這一段是整個硬體系統與外部記憶體互動的入口。先看懂 I/O，就能理解後面狀態機為什麼要一直切換 CEN、WEN、A、D。
二、常數與 FSM State 定義26–66定義 GREEN、NPIX、MAX_LABELS 與所有狀態編碼。這裡把作業的核心常數集中定義。尤其 GREEN = 32'h0000_FF00 對應 Lab7 畫框要求；state 編碼則決定整個控制流程。
三、內部暫存器、陣列與資料結構67–156包含 histogram、line buffer、union-find、bbox table 與各種控制計數器。這一段是資料路徑的核心。你可以從這裡看出設計不是把整張圖存進大陣列，而是透過 line buffer、histogram、parent table 逐步完成處理。
四、輔助函式與 Task157–350包含 Reflect-101、RGB-to-Gray、Gaussian、find_root、update_bbox、union_pair 等可重用邏輯。這一段把會重複使用的運算封裝成 function/task，使主 FSM 不需要把所有細節攤開。
五、CCL 組合邏輯351–387在 S_CCL_SCAN 狀態時，即時計算 ccl_fg、鄰居 label 與 cur_label_comb。CCL 是整份作業最重要的地方之一。這裡會看到 8-connected 的鄰居判定是如何組合出來的。
六、同步 always、reset 與預設控制388–413clock 上升緣更新主要暫存器，reset 時將系統回到初始狀態。這一段決定所有狀態與記憶體控制訊號的時序行為，是理解 RTL 是否同步正確的關鍵。
七、Input / RGB-to-Gray / Original Backup414–449S_IDLE、S_LOAD、S_GRAY：開始讀圖、轉灰階、把灰階寫入 UrSRAM，並備份原圖到 AnsSRAM。這一段把前處理整合在一個主要 state。看懂後，你就能知道整張圖是怎麼先被準備好，提供後面的 Gaussian 和畫框使用。
八、Histogram Clear 與 Gaussian Line Buffer 初始化450–539清空 histogram，並從 UrSRAM 載入三列資料到 line buffer。這一段是 Gaussian 的前置準備。因為 3×3 filter 需要上下左右鄰居，所以必須先把 prev/curr/next row 放進 line buffer。
九、Gaussian Filtering 與 Histogram Construction540–558利用 gaussian_lb() 計算平滑灰階，同步更新 histogram 與 sum_total。這一段是後續 threshold 的基礎。先降低雜訊，Otsu 才會更穩定。
十、Otsu Thresholding559–639把 Otsu 計算拆成多個 state：scan、lhs、denom、square、compare。這是整份程式最像 datapath optimization 的地方。把大乘法拆開，有助於 synthesis 與 timing。
十一、High-Pixel Counting 與 Auto-Polarity640–659統計 histogram 中大於 otsu_t 的 pixel 數量，若超過半張圖就反相。有些圖案做完 threshold 後，前景與背景可能反過來。這一段就是根據整體亮暗比例，自動修正 foreground 定義。
十二、Union-Find / BBox Table 初始化660–699初始化 parent[]、bbox_valid[]、bbox_border[] 以及 bbox 座標表。CCL 與 BBox 的資料結構在這裡被清成乾淨狀態。沒有這一步，上一張影像的 label 資料會污染下一張。
十三、CCL Line Buffer 初始化與 8-Connected CCL 掃描700–777重新載入 CCL line buffer，並在 S_CCL_SCAN 中做 binary mask、label assignment、union 與 bbox update。這是整份 code 最重要的核心階段。它把 Gaussian、Threshold、Polarity 結果轉成 component labels，並同時累積出 bbox。
十四、CCL 跨列更新與 Root Label Merge778–832處理 CCL line buffer row update，以及把非 root label 的 bbox 合併回 root label。這一段解決 union-find 後的 label 等價問題，確保同一物件的 bbox 會被整合到同一個 root component。
十五、物件過濾、BBox Overlay 與特殊補框833–899排除邊界物件與太小物件，再把有效 bbox 畫成綠色框；某些情況還有 special box compensation。這一段直接決定最後結果圖長什麼樣子，也最接近你在 bmp 圖上看到的綠色框效果。
十六、Done 與 Testbench 驗證觀念900–916S_DONE 拉高 done，testbench 再接手做 golden image comparison。RTL 到這裡就完成了，但整個作業流程還有 testbench 驗證這一步。這一段把 RTL 的終點和驗證流程串起來。
