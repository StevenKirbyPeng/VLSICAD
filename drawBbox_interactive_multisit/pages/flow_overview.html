作業流程圖

閱讀階段地圖

01

Module 介面與記憶體協定

這一段是整個硬體系統與外部記憶體互動的入口。先看懂 I/O，就能理解後面狀態機為什麼要一直切換 CEN、WEN、A、D。

02

常數與 FSM State 定義

這裡把作業的核心常數集中定義。尤其 GREEN = 32'h0000_FF00 對應 Lab7 畫框要求；state 編碼則決定整個控制流程。

03

內部暫存器、陣列與資料結構

這一段是資料路徑的核心。你可以從這裡看出設計不是把整張圖存進大陣列，而是透過 line buffer、histogram、parent table 逐步完成處理。

04

輔助函式與 Task

這一段把會重複使用的運算封裝成 function/task，使主 FSM 不需要把所有細節攤開。

05

CCL 組合邏輯

CCL 是整份作業最重要的地方之一。這裡會看到 8-connected 的鄰居判定是如何組合出來的。

06

同步 always、reset 與預設控制

這一段決定所有狀態與記憶體控制訊號的時序行為，是理解 RTL 是否同步正確的關鍵。

07

Input / RGB-to-Gray / Original Backup

這一段把前處理整合在一個主要 state。看懂後，你就能知道整張圖是怎麼先被準備好，提供後面的 Gaussian 和畫框使用。

08

Histogram Clear 與 Gaussian Line Buffer 初始化

這一段是 Gaussian 的前置準備。因為 3×3 filter 需要上下左右鄰居，所以必須先把 prev/curr/next row 放進 line buffer。

09

Gaussian Filtering 與 Histogram Construction

這一段是後續 threshold 的基礎。先降低雜訊，Otsu 才會更穩定。

10

Otsu Thresholding

這是整份程式最像 datapath optimization 的地方。把大乘法拆開，有助於 synthesis 與 timing。

11

High-Pixel Counting 與 Auto-Polarity

有些圖案做完 threshold 後，前景與背景可能反過來。這一段就是根據整體亮暗比例，自動修正 foreground 定義。

12

Union-Find / BBox Table 初始化

CCL 與 BBox 的資料結構在這裡被清成乾淨狀態。沒有這一步，上一張影像的 label 資料會污染下一張。

13

CCL Line Buffer 初始化與 8-Connected CCL 掃描

這是整份 code 最重要的核心階段。它把 Gaussian、Threshold、Polarity 結果轉成 component labels，並同時累積出 bbox。

14

CCL 跨列更新與 Root Label Merge

這一段解決 union-find 後的 label 等價問題，確保同一物件的 bbox 會被整合到同一個 root component。

15

物件過濾、BBox Overlay 與特殊補框

這一段直接決定最後結果圖長什麼樣子，也最接近你在 bmp 圖上看到的綠色框效果。

16

Done 與 Testbench 驗證觀念

RTL 到這裡就完成了，但整個作業流程還有 testbench 驗證這一步。這一段把 RTL 的終點和驗證流程串起來。
